# 07. 문제 해결 기록

실습 중 오류가 발생하거나 예상과 다른 결과가 나왔을 때 무엇을 확인했는지 기록했습니다.

## 1. 데이터 INSERT 중 시간 초과

**문제:** Python으로 회원을 저장하는 과정에서 MySQL 오류 `1205 (Lock wait timeout)`가 발생했습니다.

**확인한 내용:** 다른 작업이 데이터를 잠그고 있는지 알아보기 위해 트랜잭션(작업을 묶어 처리하는 단위)과 잠금 대기 정보를 조회했습니다.

**처리 결과:** 끝나지 않은 작업이 있는지 점검한 후 다시 실행했고, 회원 데이터 저장을 완료했습니다.

**생각해 본 원인:** 앞서 실행한 `START TRANSACTION`을 `COMMIT`이나 `ROLLBACK`으로 끝내지 않은 것이 원인일 수 있습니다. 다만 어떤 연결에서 잠금이 발생했는지 정확히 확인하지 못했으므로 **추정으로만 기록합니다.**

## 2. 인덱스 비교 중 확인한 점

**문제:** 회원 ID와 청취 날짜를 함께 사용하는 인덱스를 만들었더니 기존 회원 ID 인덱스가 목록에서 보이지 않았습니다.

**확인한 내용:** 새 인덱스도 회원 ID를 기준으로 데이터를 찾을 수 있었습니다. MySQL이 필요에 따라 기존 자동 인덱스를 정리할 수 있다는 점을 알게 됐습니다. 회원과 청취 기록을 연결하는 외래키는 유지되었습니다.

**처리 결과:** 회원 ID만 사용하는 인덱스를 다시 만들고, 두 인덱스를 각각 지정해 조회 시간을 5회씩 측정했습니다.

**관련 문서:** [인덱스 성능 비교](04_index_tuning.md)

## 배운 점
오류 메시지나 측정 숫자만 보고 판단하지 않고 **현재 DB 상태를 확인하는 과정**이 중요하다는 것을 배웠습니다.
