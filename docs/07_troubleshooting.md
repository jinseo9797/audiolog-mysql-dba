# 07. 문제 해결 기록

실습 중 예상과 다른 결과가 나온 사례를 정리했습니다.

## 1. 회원 데이터 INSERT 중 시간 초과

**현상:** Python INSERT에서 MySQL 오류 `1205 (Lock wait timeout)`가 발생했습니다.

**확인:** `information_schema.innodb_trx`와 `sys.innodb_lock_waits`로 트랜잭션과 잠금 대기를 조회했습니다. 미완료 트랜잭션을 점검한 후 다시 실행하자 회원 10건 INSERT에 성공했습니다.

**주의:** 어떤 세션이 잠금을 일으켰는지는 확인하지 못했습니다. 따라서 정확한 원인을 해결했다고 단정하지 않습니다.

## 2. 단일 FK 인덱스가 보이지 않음

**현상:** `(user_id, listened_at DESC)` 복합 인덱스를 만든 뒤 기존 `user_id` 인덱스가 보이지 않았습니다.

**확인:** FK 제약조건은 그대로 남아 있었습니다. MySQL은 복합 인덱스가 FK 검사에 필요한 역할을 할 수 있으면 기존 자동 인덱스를 제거할 수 있습니다.

**조치:** 기존 복합 인덱스를 숨기고 측정한 결과는 단일 인덱스 비교로 보기 어려웠습니다. 비교용 단일 인덱스를 새로 만들고 각 인덱스를 지정해 5회씩 다시 측정했습니다.

**관련 자료:** [인덱스 보고서](04_index_tuning.md)

## 느낀 점
오류 메시지를 보는 것에서 끝내지 않고 현재 DB 상태와 실행 계획을 확인해야 결과를 정확하게 설명할 수 있다는 점을 배웠습니다.
