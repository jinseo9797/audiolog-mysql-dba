# 07. 문제 해결 기록

실습 중 예상과 다른 결과가 나온 사례를 정리했습니다.

## 1. 회원 데이터 INSERT 중 시간 초과

**현상:** Python INSERT에서 MySQL 오류 `1205 (Lock wait timeout)`가 발생했습니다.

**확인:** `information_schema.innodb_trx`와 `sys.innodb_lock_waits`로 트랜잭션과 잠금 대기를 조회했습니다. 미완료 트랜잭션을 점검한 후 재실행해 회원 데이터 INSERT를 완료했습니다.

**주의:** 어떤 세션이 잠금을 일으켰는지는 확인하지 못했습니다. 따라서 정확한 원인을 해결했다고 단정하지 않습니다.

실습 중 하나의 쿼리 파일을 start transaction 해두었고 rollback 혹은 commit으로 마무리하지 않아 발생한 이슈로 예상하고 있습니다.

## 2. 인덱스 비교 중 확인한 점

**현상:** 회원 ID와 청취 날짜를 함께 사용하는 인덱스를 만들자 기존 회원 ID 인덱스가 목록에서 사라졌습니다.

**이유:** 새 인덱스도 회원 ID로 검색할 수 있어 MySQL이 기존 인덱스를 정리한 것으로 확인했습니다. 회원과 청취 기록을 연결하는 FK는 유지되었습니다.

**조치:** 정확히 비교하기 위해 회원 ID만 사용하는 인덱스를 다시 만든 뒤 두 인덱스의 조회 시간을 각각 5회 측정했습니다.

**관련 자료:** [인덱스 성능 비교](04_index_tuning.md)

## 느낀 점
오류 메시지를 보는 것에서 끝내지 않고 현재 DB 상태와 실행 계획을 확인해야 결과를 정확하게 설명할 수 있다는 점을 배웠습니다.
